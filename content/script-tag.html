Adding the script#

The tracker is a single self-hosted file — px.js, served from your own Pulse deployment. It sets no cookies, writes nothing to storage, and wraps its entire body in try/catch so a failing analytics call can never break the host page.

<script defer data-key="YOUR_INGEST_KEY" src="https://your-pulse.vercel.app/px.js"></script>
defer
Load the script without blocking rendering. Recommended, but not required.
data-key
Required. Your project's public ingest key. Without it the script does nothing and returns silently.
src
Points at /px.js on your deployment. The collector origin defaults to this URL's origin unless you override it with data-host.

All behaviour is configured through data-* attributes on that same tag — there is no separate config object for the script build.

Configuration: data-* attributes#

Attributes are read once, from the script tag itself, when the tracker loads. Boolean flags are toggled by presence — the attribute needs no value.

AttributeTypeDefaultWhat it does
data-key required string — The project's public ingest key. If missing, the tracker returns immediately and sends nothing.
data-host string script origin Override the collector origin. Useful if you serve px.js from a different host than your Pulse app.
data-manual flag off Disable automatic pageview tracking. You drive pageviews yourself by calling pulse().
data-respect-dnt flag off Drop events from browsers sending Do Not Track or Global Privacy Control signals.
data-local flag off Also track localhost, 127.*, ::1, *.local and file://. Off by default so development traffic doesn't pollute your numbers.
data-exclude string — Comma-separated paths to skip. A trailing * makes it a prefix match.

Example: a fully configured tag

<script
  defer
  data-key="YOUR_INGEST_KEY"
  src="https://your-pulse.vercel.app/px.js"
  data-respect-dnt
  data-exclude="/admin*,/preview,/draft*"
></script>

This tracks everything except your admin area and preview/draft routes, and honours Do Not Track. Pageviews are still automatic because data-manual is absent.

Excludes are also enforced server-side. Each project has its own Excluded paths setting in the dashboard that applies to all traffic regardless of the tag. Use data-exclude for per-page-embed control; use the dashboard setting for a project-wide rule.

The pulse() function#

Once the script loads it exposes one global: window.pulse. Its signature is deliberately minimal.

pulse(name: string, props?: object) => void

Track a custom event

pulse('signup', { plan: 'pro' });
pulse('cta_click', { location: 'hero' });
pulse('video_play');            // properties are optional

Track a pageview manually

Call pulse() with no name, or the name 'pageview', to record a pageview for the current URL. This is what you use in data-manual mode.

pulse();            // pageview for the current URL
pulse('pageview');  // identical

Track revenue

Revenue rides along inside the props object under a revenue key. The collector lifts it out and normalizes it.

pulse('purchase', {
  revenue: { amount: 29, currency: 'USD' },
  plan: 'pro'
});

See Revenue tracking for currency handling and how it merges with Stripe.

Pageviews are automatically deduped against the last URL sent, so a router that both calls pushState and emits its own navigation event won't double-count a single route change.

Calling pulse() before the script loads#

Because the script is deferred, window.pulse may not exist yet when your page code runs. Define a tiny stub that queues calls; the tracker drains the queue the moment it loads.

<script>
  window.pulse = window.pulse || function () {
    (pulse.q = pulse.q || []).push(arguments);
  };
</script>
<script defer data-key="YOUR_INGEST_KEY" src="https://your-pulse.vercel.app/px.js"></script>

Now any pulse('event', …) call made before the tracker finishes downloading is buffered on pulse.q and replayed in order once it's ready. Put the stub in your document <head>, before any code that might fire an event.
