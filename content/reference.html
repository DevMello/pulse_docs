Wire format#

Both the script and the npm package POST a small JSON body to /api/event as text/plain — which keeps it a CORS "simple request" with no preflight, so a pageview costs exactly one round trip. Keys are single letters because this is the hot path.

POST https://your-pulse.vercel.app/api/event
Content-Type: text/plain

{
  "k": "YOUR_INGEST_KEY",          // project ingest key
  "n": "pageview",                  // event name
  "u": "https://acme.dev/pricing?utm_source=hn",  // full href
  "r": "https://news.ycombinator.com/",           // referrer, or null
  "w": 1440,                        // viewport width (server buckets it)
  "p": { "plan": "pro",             // custom props (optional)
         "revenue": { "amount": 29, "currency": "USD" } }
}
KeyMeaningNotes
kIngest keyRequired. Identifies the project.
nEvent nameRequired. pageview or a custom name.
uPage hrefFull URL. Only the pathname and UTM keys are kept — the rest of the query string is dropped before the row is written and never stored.
rReferrerdocument.referrer or null. Normalized and grouped server-side.
wViewport widthRaw pixels; bucketed server-side. Not identifying on its own.
pPropertiesOptional. Scalar props plus an optional revenue object.

Transport uses navigator.sendBeacon when available — it survives the page being unloaded — and falls back to fetch with keepalive: true. Either way, the client never reads the response.

You can integrate without any Pulse client at all — from a backend, a webhook, or curl — by posting this exact body to /api/event. A CORS preflight (OPTIONS) is answered for JSON Content-Type if you post from a browser.

What the server does with your event#

The client stays dumb on purpose. Everything below is derived on the edge from data the request already carries, then the raw inputs are discarded.

Derived & stored

  • Device, browser, OS — from the User-Agent
  • Country & region — from edge geo headers
  • Referrer host + channel group
  • UTM source / medium / campaign / term / content
  • Screen-size bucket — from viewport width
  • A salted daily visitor hash

Discarded, never stored

  • The raw IP address (used, then dropped)
  • The full User-Agent string
  • Everything in the query string except UTM keys
  • The URL fragment (except a leading #/ route)

HTTP responses#

The client is fire-and-forget and ignores the response, so the collector stays deliberately quiet: it only distinguishes cases the site owner can act on. A status code never reveals whether a key exists, a domain is allow-listed, or a bot evaded the filter.

StatusMeaningWhen
202AcceptedThe normal success — and most quiet rejections (unknown key, archived project, bot, excluded path, DNT). Indistinguishable from outside on purpose.
400Bad payloadThe one rejection worth surfacing: malformed JSON, missing key, missing/empty name, or an unparseable URL. It means the integration is broken.
429Rate limitedToo many events from one IP. Includes a Retry-After header. The limiter is a spike damper, not a hard quota.
503Not configuredThe deployment is missing its service-role key, or a lookup failed. A server-side misconfiguration to fix.
