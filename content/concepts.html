Pageviews & SPA routing#

By default Pulse tracks a pageview on first load and on every client-side navigation. It does this by wrapping the History API and listening for the browser's own navigation events.

SignalFires a pageview?Why
history.pushStateYesThe normal SPA navigation. Patched so the original still runs, then a pageview fires.
popstateYesBack / forward navigation.
hashchangeYesHash routers change the URL without touching History.
history.replaceStateNoRouters use it for query-param updates and scroll restoration — not real navigations.

Dedupe

Every pageview is checked against the last URL sent. If a router both calls pushState and fires its own event for one route change, only one pageview is recorded.

Prerender awareness

Chrome prerenders pages a user may never actually look at. The script defers the initial pageview until the page becomes visible, so a prerendered-but-unseen page isn't counted — exactly the vanity inflation the public stats page is designed to avoid.

Hash routes become distinct pages

The History API never sees the URL fragment, so the collector treats a leading #/ as part of the path. example.com/#/settings is recorded as /#/settings, meaning hash-router views show up as separate pages instead of everything collapsing onto /.

Some frameworks don't route through pushState. Next.js App Router, vue-router and SvelteKit can navigate without it, so the History patch may miss pages. For those, use the framework adapter (which drives pageviews from the router) or call pageview() yourself. See Frameworks.

Custom events#

A custom event is any named signal that isn't a pageview — a signup, a click, a feature toggle, a funnel step. Give it a name and, optionally, a flat bag of scalar properties.

import { track } from '@pulse/sdk';

// Simple named event
track('newsletter_subscribe');

// With properties — strings, numbers, booleans
track('plan_selected', { plan: 'pro', annual: true, seats: 5 });

// The script-tag equivalent
// pulse('plan_selected', { plan: 'pro', annual: true, seats: 5 });

Naming

  • Names are trimmed and truncated to 64 characters server-side.
  • An empty name is rejected (400).
  • The name 'pageview' is reserved — it routes to pageview tracking.
  • Prefer stable, lowercase, snake_case names (cta_click) so they group cleanly in the dashboard's funnels and event breakdowns.

Properties

  • Up to 24 keys; extra keys are dropped.
  • String values are truncated to 500 characters.
  • Only string, number (finite), and boolean are kept. Nested objects/arrays are ignored — except the reserved revenue object.
